**怎么判断一个算子 bound 在哪里**
假设硬件有：
`峰值算力 = 1000 TFLOPS 峰值带宽 = 3 TB/s`
分界点是：
`1000 TFLOPS / 3 TB/s = 333 FLOPs/byte`
如果算子的算术强度低于 333 FLOPs/byte，理论上更容易带宽 bound。  如果高于它，理论上更容易计算 bound。

典型例子：
`GEMM / 大矩阵乘：更容易计算 bound 
`LayerNorm / RMSNorm / elementwise / softmax：更容易带宽 bound 
`Attention prefill：优化后可能接近计算 bound 
`Attention decode / KV cache 读取：常常带宽 bound`



  
场景1：算子一致性指的是相同的输入送给同一个算子，多次执行的结果相等，算子产生不确定性的原因主要是算子内部使用了atomicadd等不保证累加许的指令造成的结果不一致，当前为了性能，部分算子默认状态时非确定性的，如果想开启确定性计算可以使用环境变量来控制；
场景2：triton算子对于部分入参使用tl.constexpr修饰，为了提前进行资源的分配，向量维度的确定，计算分支的确定，从而优化性能，所谓是“GPU 高性能来自“专门化”。” 
问题：场景1中不确定性来提升性能，场景2中又通过确定性来提升性能，似乎有一些矛盾？
解释：不矛盾，场景1中允许执行顺序不固定 -> 并行调度更自由 -> 性能更好；强制结果完全一致 -> 调度/累加顺序受限 -> 性能下降
		     场景2中编译期信息越固定 -> 生成代码越专门化 -> 性能更好；运行时什么都动态 -> 代码更通用保守 -> 性能更差
		前者给硬件调度更多自由，后者给编译器更多已知信息，所以都能提升性能，并不冲突，可以同时存在
