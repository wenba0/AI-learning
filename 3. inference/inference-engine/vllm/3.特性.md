开了flashcomm之后会有问题： tp8 mtp5的场景，比如输入10个token，图执行的size需要是6的倍数（12）但sp又需要是8的倍数，会出现冲突

deepseekv3的mtp：num_hidden_layers=61,num_nextn_predict_layers=1,主模型0-60层，mtp61层，mtp层的输入为上一个hidden_states和新的token，num_speculative_tokens>num_nextn_predict_layers的情况下会重复使用该mtp层

```
阶段 1: 主模型前向 (生成 E + hidden_states)
─────────────────────────────────────────
  输入: [A, B, C, D]  (4 个 token)
  主模型 61 层 → hidden_states (每个 token 都有)
  lm_head → 采样得到 token E
  ★ hidden_states[D的位置] 被保存

阶段 2: MTP 生成 draft tokens (F 和 G)
─────────────────────────────────────────
  Step 0 (第1个MTP层):
    输入: previous_hidden = 主模型对D的hidden_states
          inputs_embeds = embed(E)  ← E是主模型刚采样的token
    MTP层61 → shared_head → logits → 采样得到 F

  Step 1 (第2个MTP层, 循环使用层61):
    输入: previous_hidden = MTP Step0 输出的hidden_states
          inputs_embeds = embed(F)  ← F是上一步MTP猜的token
    MTP层61 → shared_head → logits → 采样得到 G

  draft_tokens = [F, G]

阶段 3: 主模型验证 (关键!)
─────────────────────────────────────────
  输入: [A, B, C, D, E, F, G]  ← 一次性送入 7 个 token!
       位置:  0  1  2  3  4  5  6

  不是两个 batch! 是一个 batch, 一次前向!
  主模型对每个位置都输出 logits:
    位置 0-3: [A,B,C,D] 的 logits (不需要)
    位置 4:   主模型对 E 的预测 → 采样得到 E' (用于验证 E)
    位置 5:   主模型对 F 的预测 → 采样得到 F' (用于验证 F)
    位置 6:   主模型对 G 的预测 → 采样得到 G' (用于验证 G)
```

##### DP rank之间的同步

ModelRunner中的_sync_batch_across_dp函数会在DP rank之间同步，num_tokens_padded是每个DP rank的token数量，vLLM ascend会多一个cudagraph_mode的对齐，如果开了MC2就会使能allow_dp_padding，通过allreduce来使得每个rank都能拿到其他rank的信息，对于dense模型该函数中会调用should_skip_allreduce_across_dp_group来判断 直接跳过同步

```
假设 dp_size=2，rank0 的 num_tokens_padded=120, cudagraph_mode=2，rank1 的 num_tokens_padded=96, cudagraph_mode=1。
all-reduce 前：
rank0 tensor 近似是 [[120, 0], [2, 0]]
rank1 tensor 近似是 [[0, 96], [0, 1]]
all-reduce 后，两边都会变成 [[120, 96], [2, 1]]
```

如果allreduce同步的话，MC2按uniform模式执行， 需要传入mc2_mask(算子对应的输入是x_active_mask)来标识哪些是pad的，global_bs=0，如果不同步的话 按 ragged 模式执行mc2,不需要传入mask，global_bs=num_tokens_per_tp_rank * self.ep_world_size作为算子容量上限

```
_max_global_bs = num_tokens_per_tp_rank * self.ep_world_size
# When allreduce across DP is not skipped, tokens are uniform across ranks:
# use global_bs=0 (uniform mode) and pass mc2_mask.
# When allreduce is skipped, tokens may differ per rank:
# use the real global_bs and do NOT pass mc2_mask.
self.global_bs = _max_global_bs if should_skip_allreduce_across_dp_group(vllm_config) else 0
```

2个头(h1 h2)4张卡的情况：

tp4: 四张卡上分别是h1 h2 h1 h2，其中卡0和卡2存的kvcache是一样的，只有一条数据输入，

tp2 dp2: 四张卡上也分别是h1 h2 h1 h2, 但是此处的卡0与卡2存的kvcache是不一样的，有两条数据输入，

相当于开了dp2之后2条数据的kvcache与纯tp4的一条数据的kvcache大小是一样的，即达到了省显存的目的。
